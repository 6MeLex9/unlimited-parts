**История перемещений #17 «недавно просмотренные учебники»** (шаги 14–16, 24):

| Шаг | Board Column | Swimlane |
| --- | --- | --- |
| 14 | Committed → **Approved QA** | Default |

**Итоговое состояние колонки «Approved QA» — 2 карточки при лимите 1**
(как на рисунке методички после шага 24): #17 на дорожке «Ускоренная»,
#18 на дорожке Default.

Проверка:

```
./scripts/check_wip.ps1
[WIP EXCEEDED] колонка 'Approved QA': 2 элементов при лимите 1
    - #17 Как клиент, я хочу видеть недавно просмотренные учебники
    - #18 Как клиент, я хочу запросить новые материалы
```

Состояние до перемещений (WIP соблюдён) — снимок
`data/lab2.2-board-state-compliant.json`:

```
./scripts/check_wip.ps1 -StateFile data/lab2.2-board-state-compliant.json
[OK] колонка 'Approved QA': 1/1
```

> В GitHub Projects нет встроенного WIP-лимита и разделения колонок, поэтому
> ограничение выражено полем `Board Column` + проверкой скрипта, а разделение
> Doing/Done — атрибутами конфигурации доски. Смысл и результат те же.

## Задача 6: настройка процесса

В Azure создаётся унаследованный процесс «Мой Scrum» и в нём поле
`PUL Ticket ID` для Product Backlog Item.

| Шаг методички | Реализация в GitHub |
| --- | --- |
| 3. Вкладка «Процесс» | описание процесса в `data/demo-generator/board-config.json` (`process`) |
| 4–5. Создать унаследованный процесс «Мой Scrum» | раздел `process.inheritedProcessName`, базовый процесс Scrum |
| 7–9. PBI → New field → «PUL Ticket ID» | поле Project v2 **`PUL Ticket ID`** (текстовое) создано через GraphQL |
| 10. Группа `PartsUnlimitedGroup`, метка «Ticket ID» | `process.field.group` + подпись `label` |
| 11–15. Переключить проект на «Мой Scrum» | все элементы используют единый набор полей проекта (см. `lab2.2-process.md`) |
| 19–21. Заполнить Ticket ID у первого PBI | **#3 → `PUL-1042`**, #17 → `PUL-1043` |

Поле проверено: в проекте у элемента #3 стоит `PUL Ticket ID = PUL-1042`, и это
значение доступно в фильтрах и в виде `Backlog`.
